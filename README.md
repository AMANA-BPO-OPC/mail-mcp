# خادم البريد المتعدد لكلود

خادم يربط كلود مباشرة بعدة حسابات جيميل أو مساحات عمل جوجل، بدون تحويل الرسائل. يتيح لكلود من الجوال أو الحاسوب أن:

- يعرض الحسابات المربوطة.
- يبحث في حساب واحد أو في كل الحسابات معاً.
- يقرأ أي محادثة كاملة ومرفقاتها.
- يرسل رسالة جديدة أو يرد من الحساب الذي تختاره.
- ينشئ مسودة بدون إرسال.

تعليمات الخادم لكلود تلزمه بعرض الرسالة والحساب المرسِل والمستلمين عليك قبل أي إرسال، وألا يرسل إلا بعد موافقتك.

---

## كيف يعمل

```
كلود (جوال / حاسوب / متصفح)
      │  مصادقة بكلمة مرورك عند أول ربط
      ▼
الخادم  ──►  حساب ١  حساب ٢  حساب ٣ ...  (عبر واجهة جيميل البرمجية)
```

- **حماية الخادم من الغرباء:** لا يدخل أحد إلى الخادم إلا بعد إدخال كلمة مرور المالك في صفحة الموافقة. لا يُقبل الرجوع إلا إلى عناوين كلود الرسمية. صلاحية الدخول ساعة واحدة وتتجدد تلقائياً، ويمكن إلغاء كل الجلسات بزر واحد.
- **حماية صلاحيات جوجل:** تُخزَّن مشفّرة داخل قاعدة البيانات. حذف أي حساب من لوحة الإدارة يلغي صلاحيته عند جوجل أيضاً.
- **الصلاحيات المطلوبة من جوجل:** القراءة، وإنشاء المسودات، والإرسال. لا يملك الخادم صلاحية حذف الرسائل.

## خطوات الإعداد (للفريق التقني)

### ١) مشروع في منصة جوجل السحابية (مرة واحدة)

1. أنشئ مشروعاً جديداً في منصة جوجل السحابية، وفعّل فيه واجهة جيميل البرمجية (Gmail API).
2. في إعدادات شاشة الموافقة (Google Auth Platform):
   - نوع الجمهور: **External**، لأن حساباتك موزعة على عدة مساحات عمل منفصلة.
   - أضف الصلاحيتين:
     `https://www.googleapis.com/auth/gmail.readonly`
     `https://www.googleapis.com/auth/gmail.compose`
   - **مهم:** غيّر حالة النشر إلى **In production**. إذا بقيت على Testing تنتهي صلاحية كل حساب بعد ٧ أيام وتضطر لإعادة الربط.
3. أنشئ معرّف عميل من نوع **Web application**، وأضف عنوان الرجوع التالي:
   `https://<عنوان-الخادم>/admin/google/callback`
4. احفظ قيمتي `Client ID` و`Client secret`.

**ما ستراه عند الربط:** لأن التطبيق غير موثّق من جوجل، تظهر شاشة تحذير "Google hasn't verified this app". اضغط Advanced ثم المتابعة. هذا متوقع للاستخدام الشخصي، والحد ١٠٠ مستخدم وأنت مستخدم واحد.

**إذا رفضت إحدى مساحات العمل الربط:** مدير تلك المساحة يضيف معرّف العميل إلى قائمة التطبيقات الموثوقة من:
Admin console ← Security ← Access and data control ← API controls ← Manage Third-Party App Access.

### ٢) توليد الأسرار

```bash
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"   # ENCRYPTION_KEY
python3 -c "import secrets; print(secrets.token_urlsafe(32))"                                 # SESSION_SECRET
python3 -c "import secrets; print(secrets.token_urlsafe(24))"                                 # ADMIN_PASSWORD
```

انسخ `.env.example` إلى `.env` واملأ القيم. **لا ترفع ملف `.env` إلى المستودع أبداً.**

| المتغير | الوصف |
|---|---|
| `PUBLIC_URL` | العنوان العام للخادم بصيغة https، بدون شرطة في آخره |
| `ADMIN_PASSWORD` | كلمة مرور المالك، ١٦ حرفاً على الأقل. يحتفظ بها عبدالرحمن فقط |
| `ENCRYPTION_KEY` | مفتاح تشفير صلاحيات جوجل. **إذا ضاع تضطر لإعادة ربط كل الحسابات** |
| `SESSION_SECRET` | سرّ توقيع جلسة لوحة الإدارة |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | من الخطوة ١ |

### ٣) الاستضافة

يحتاج الخادم ثلاثة أشياء:
- عنوان عام بشهادة https.
- **قرص دائم** على المسار `/data`، لأن قاعدة البيانات تُحفظ فيه.
- تشغيل مستمر.

أي مزوّد يشغّل حاويات دوكر مع قرص دائم يكفي: خادم افتراضي خاص مع عاكس وكيل يصدر الشهادة تلقائياً، أو منصة حاويات تدعم الأقراص الدائمة. **لا تستخدم منصة بدون قرص دائم**، فستُمسح الحسابات المربوطة عند كل إعادة تشغيل.

```bash
docker build -t gmail-mcp .
docker run -d --name gmail-mcp --restart unless-stopped \
  --env-file .env -v gmail_mcp_data:/data -p 8000:8000 gmail-mcp
```

ثم ضع أمامه عاكساً وكيلاً بشهادة https يوجّه النطاق إلى المنفذ 8000.

### ٤) ربط حسابات البريد (يقوم به المالك)

1. افتح `https://<عنوان-الخادم>/admin` وادخل بكلمة مرور المالك.
2. اضغط "ربط حساب جوجل جديد"، واختر الحساب، ووافق على **كل** الصلاحيات.
3. كرر الخطوة لكل حساب.
4. لكل حساب، اكتب **اسماً مختصراً** مثل "مكشاتي" أو "ولف باك" لتستخدمه في حديثك مع كلود، و**اسماً ظاهراً** يراه المستلم.

### ٥) إضافة الموصل في كلود (يقوم به المالك)

1. في كلود: الإعدادات ← الموصلات ← إضافة موصل مخصص.
2. الرابط: `https://<عنوان-الخادم>/mcp`، واترك الإعدادات المتقدمة فارغة.
3. اضغط ربط. تفتح صفحة الخادم، فأدخل كلمة مرور المالك ثم اضغط موافقة.
4. يعمل الموصل بعدها من الويب والجوال وتطبيق سطح المكتب على نفس الحساب.

**ملاحظة:** في خطة الفريق، المالك هو من يضيف الموصل المخصص على مستوى المؤسسة، ثم يربطه كل عضو بحسابه. لا تشارك كلمة مرور المالك مع أحد، فمن يملكها يصل إلى كل البريد.

## الصيانة والأمان

- **إذا ظهر عند حساب "يحتاج إعادة ربط":** اضغط "إعادة الربط" بجانبه. يحدث هذا إذا غُيّرت كلمة مرور الحساب أو أُلغيت الصلاحية.
- **إذا شككت في تسرب:** اضغط "إلغاء كل جلسات كلود"، وغيّر `ADMIN_PASSWORD`، ثم أعد تشغيل الخادم وأعد الربط.
- **النسخ الاحتياطي:** احفظ نسخة من قرص `/data` ومن `ENCRYPTION_KEY` في مكانين منفصلين. القاعدة بدون المفتاح لا تُقرأ.
- **محاولات الدخول:** تُقفل محاولات الدخول ١٥ دقيقة بعد ١٠ محاولات خاطئة.
- **محتوى الرسائل:** نص الرسائل الواردة قد يحتوي تعليمات مدسوسة. كلود يعامله كبيانات، ولا يرسل شيئاً بدون موافقتك الصريحة.

## حدود الإصدار الحالي

- يقرأ المرفقات: PDF (والممسوح ضوئياً يُعرض صوراً)، وورد docx، وإكسل xlsx/xls/csv، وباوربوينت pptx، والصور (منها HEIC)، والنصوص، وملفات zip. الصيغ القديمة doc/ppt/rtf غير مدعومة.
- لا يرسل مرفقات مع الرسائل.
- لا يحذف الرسائل ولا ينقلها ولا يضع عليها تصنيفات، عن قصد.
- يُقتطع نص الرسالة الطويلة جداً عند ١٥ ألف حرف.

## الاختبار

```bash
pip install -r requirements.txt
python3 -I tests/test_server.py
```

الاختبار يحاكي واجهة جيميل ويغطي ٣٣ حالة: المصادقة، ورفض الطلبات غير المصرّح بها، والبحث في كل الحسابات، والقراءة، والإرسال، والرد، والمسودات، ولوحة الإدارة.
